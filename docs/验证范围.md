## Android 14 模拟器验证（授权跳转与崩溃弹窗修复）

环境同上（`sdk_gphone64_x86_64`，SDK 34，`emulator-5554`）。本节只覆盖 AOSP 的 `SettingsGoogle`，不代表 HyperOS 或任何厂商皮肤。

- 复现了“点去授权直接回桌面”这一类故障的机制：把 `EXTRA_NOTIFICATION_LISTENER_COMPONENT_NAME` 按官方文档写成 `ComponentName` 值（`am start --ecn`）时，`com.android.settings` 的 `NotificationAccessDetails.onAttach` 抛 `NullPointerException`（`ComponentName.getPackageName()` on null），设置进程崩溃，`topResumedActivity` 掉回桌面，本 App 侧拿不到任何异常。改传扁平字符串（`--es`）不崩，详情页正常打开；这与 `MainActivity` 里那条注释记录的取舍一致，现在有实测依据。
- 本 App 实际发出的完整 intent（扁平字符串 + `:settings:fragment_args_key` + `:settings:show_fragment_args`）端到端正常：点“去授权”后焦点转到 `Settings$NotificationAccessDetailsActivity`，无崩溃，进程存活，轨迹依次为 `permission_button_clicked` → `permission_query_result=DENIED` → `settings_start_attempt` → `settings_start_returned` → `activity_pause` → `activity_stop`。
- 新增的跳转看护未误报：正常流程轨迹中不出现 `settings_handoff_not_observed`。
- 修掉崩溃弹窗反复弹出：调用链上此前只有“问题反馈 → 清空日志”会清理崩溃日志，弹窗的“复制”“关闭”都不清理，而该文件只保留最近一次异常且不被覆盖，因此每次冷启动都会再弹。现改为“复制”“关闭”或取消时删除，仅在选择“问题反馈”时保留（反馈报告需要读它）。实测：写入一条假崩溃日志 → 启动弹出 → 点“关闭”→ 文件已删除 → 冷启动不再弹出。
- 跳转看护的“修复分支”尚未在真机上触发过：它需要系统设置页在 `startActivity` 返回后立刻消失才会走到，AOSP 上无法制造该条件；该分支只有代码审查，没有设备证据。
- 品牌判定：`Build.MANUFACTURER` 为 `Xiaomi`（含红米、POCO）时跳过详情页，直接打开 `ACTION_NOTIFICATION_LISTENER_SETTINGS` 列表页；其他机型仍走详情页 + 上述看护。理由是这个 extra 只在字符串形态下被实测通过，而列表页不接受任何 extra，不存在类型不匹配的空间。
- 该品牌分支本身未能在模拟器上真实触发：`ro.product.manufacturer` 启动后不可写，`emulator -prop` 与 root `setprop` 均无效（实测仍返回 Google）。因此只做了分段验证——列表页 action 实测能打开 `Settings$NotificationAccessSettingsActivity`；在制造厂商仍为 Google 的同一构建上，详情页路径没有回归（焦点、轨迹与看护行为与上一轮一致）。
- 品牌判定的代价与残留风险：若某台小米设备的详情页其实可用，用户只是多一次列表页滚动；若其他厂商皮肤同样会崩详情页，仍由看护降到列表页兜底。
- Lint 0 error / 9 warning；三个 JVM 自测均 `4 groups passed`。

## 尚未覆盖或需要作者确认

- 首次未授权安装、受限设置帮助和返回续接需要合适的未授权环境；不为凑测试撤销当前有效授权。
- 红米 K100 Pro Max“点去授权直接闪退/回桌面”仍未确认：没有该设备的授权轨迹、系统退出记录或 logcat，因此本版不声称已修复，也不把它推广为 HyperOS 缺少通知使用权。现在复测会留下可判读的证据：轨迹里出现 `settings_handoff_not_observed` 说明系统设置页没有真正接管焦点；`activity_stop` 之后没有 `activity_resume` 说明进程在设置页期间被终结；两者都没有则说明跳转本身正常，问题在别处。
- 状态栏与导航条适配只在 AOSP Android 14 模拟器上实测；HyperOS、MagicOS 及其他厂商皮肤的浅色图标、手势条对比度和系统栏对比度策略仍需真机确认。
- 手动重新连接、服务单独断开重连、重试耗尽和 60 秒冷却并非所有组合都做过最终设备回归。
- 最新紧凑赞赏入口的小屏滚动、人工目视效果和其他机型兼容性仍需验证。
- 微信收款人、实际扫码落地与金额选项需要作者在微信内核对；图片字节一致不等于这些项目已验证。
- 不保证所有厂商、所有受保护通知都能隐藏或恢复。
- Release 私钥与密码需要作者自行完成至少两份安全加密离线备份并验证恢复。
