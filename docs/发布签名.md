# 发布签名与密钥保管

## 公开身份信息

当前正式 Release 签名证书 SHA-256：

`E9:A8:52:67:A4:4D:A4:75:1C:D6:DD:19:9B:EA:09:1A:96:72:5D:CF:9E:22:14:33:19:47:55:4C:70:41:DE:96`

证书指纹和 APK 的 SHA-256 可以公开，用于核对下载文件。当前 v1.4.3 的 APK 校验值见 [验证范围](验证范围.md) 和 Release 附件 `SHA256.txt`。

## 不能公开的内容

- `.jks`、`.keystore`、私钥；
- keystore 密码和 key 密码；
- 真实 `keystore.properties`；
- 包含上述内容的截图、日志、聊天或备份。

这些文件均被 `.gitignore` 排除，不应作为 Release 附件上传。

## 作者备份要求

将正式 `.jks` 与真实 `keystore.properties` 一起备份到至少两个安全、加密的离线位置，并实际验证恢复。两者缺一不可。丢失私钥或密码会导致无法以同一签名发布后续升级；私钥泄露可能让他人签署同名应用。

后续版本必须沿用同一正式签名，不应通过重新生成密钥来“解决”覆盖安装失败。

## 从 Debug 测试包迁移

Debug 与 Release 签名不同，不能直接覆盖安装。迁移前，先在旧版“已隐藏”中恢复仍需立即接收的通知，再按系统流程卸载旧版、安装正式版并重新手动授权。

卸载不保证清除系统休眠记录，也不保证通知立即恢复。不要为了升级反复卸载，不要批量恢复或清除全部通知。

## 自行构建

复制 `keystore.properties.example` 为 `keystore.properties`，填写你自己的签名配置。自行生成的密钥与官方 Release 签名不同，这是正常情况；请妥善记录你自己的证书指纹，不要把它写成上方官方发布身份。
